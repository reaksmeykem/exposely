# Security Policy

## Reporting a Vulnerability

Please do not open a public GitHub issue for security-sensitive bugs.

Instead, report the issue privately to the maintainers with:

- a short summary of the issue
- affected versions or commit range
- steps to reproduce
- impact assessment
- any suggested mitigation if available

If you do not yet have a private reporting channel configured on GitHub, add one before publishing the repository broadly.

## Response Goals

- acknowledge the report within 7 days
- investigate and confirm impact
- prepare and release a fix when appropriate
- credit the reporter when they want public acknowledgment

## Scope

Please report issues such as:

- credential or token exposure
- privilege escalation
- command execution vulnerabilities
- unsafe file handling
- insecure defaults that expose local services unexpectedly

## Out of Scope

- support questions
- feature requests
- issues caused solely by local misconfiguration without security impact
